# Модель кредитного риск менеджмента

> В рамках проекта осуществляется поиск модели позволяющей прогнозировать риск неуплаты клиентом по кредиту (дефолт).

---

## Описание

Модель должна позволить банку или другой кредитной организации оценить риск по выданным займам и помочь предотвратить неисполнение кредитных обязательств клиентом.
В качестве базовой метрики принята площадь под кривой ROC (ROC-AUC). Модель считается приемлемой при ROC-AUC > 0.75.

Датасет с признаками для обучения находится в папке \raw_data и разбит на двенадцать Parquet файлов: train_data_0.pq - train_data_11.pq.

Целевая переменная 'flag' находится в папке \raw_data файл target.csv и сгрупированы по id клиента.

Датасет содержит информацию о различных атрибутах заемщиков и кредитных продуктов: о клиентах, которые уже имеют кредиты, их кредитной истории и финансовых показателях. Каждая запись в датасете представляет один конкретный кредитный продукт, выданный конкретному заемщику.

**\*\* Закодировано**: категориальные признаки приведены к числовому виду

## Используемые подходы

### Предобработка данных

Ноутбук с предобработкой данных: notebooks/Preprocessing.ipynb

1. Поскольку целиком в оперативную память датасет не помещатся, то предварительно осуществляется чтение каждого parguet-файла и преобразование типов данных (функция read_parquet_dataset_from_local), что позволяет уменьшить размер файла в оперативной памяти до 10 раз. В функции read_parquet_dataset_from_local осуществляется также удаление дубликатов и записей с пропускам, возвращает словарь признак - уникальные значения для последующего использования в OneHotEncoder. Словарь записан в файл: prep_data/unique_dict.txt.
2. Кодирование и агрегирование признаков (функция prepare_dataset).
   Кодирование признаков осуществляется с помощью OneHotEncoder. Поскольку все признаки представляют собой закодированные, либо бинаризированные значения, то принято решение все их закодировать с помощью OneHotEncoder. Дополнительные признаки не разрабатывались. Экспертно принято решение о их достаточности.
   После OHE проводилась аггрегация по 'id' клиента признаков путем их суммирования.
   На выходе функции набор parquet файлов с преобразованными типами данных, закодированными и агрегированными признаками.
3. С помощью функции prepare_full_dataset осуществлена склейка parquet файлов в один файл и соединение с целевой переменной.
   Результат: prep_data/result_dataset.pq
4. С помощью train_test_split пакета sk-learn произведено разделение данных на тренировочную и тестовую выборки в соотношении 80:20.
   Поскольку имеется существенный дисбаланс классов по целевому признаку, разделение проведено со стратификацией нему (параметр stratify).
   Тренировочноя и тестовая выборки сохранение в parquet-файлы:
       - prep_data/data_train.pq
       - prep_data/data_test.pq
5. С помощью функции prepare_scaled_files проведено масштабирование с помощью StandartScaller отдельно тренировочного и тестового датасетов. Результаты записаны в файлы:
       - prep_data/data_train_std.pq
       - prep_data/data_test_std.pq

### LightGBM c feature importance

Ноутбук: notebooks/LightGBM.ipynb

Поиск модели с помощью LightAutoML показал, что сама по себе Tuned_LightGBM дает неплохие результаты (ROC-AUC - 0,7534).
Принято решение попробовать улучшить этот результат с помощью сокращения признаков по критерию feature importance.
Обучение модели LightGBM с параметрами подобранными с помощью LightAutoML на всех признаков не дало такой метрики, ROC-AUC оказался порядка 0.71.
Однако подборов количества признаков удалось незначительно улучшить ROC-AUC посравнению с Tuned_LightGBM LightAutoML до ROC-AUC = 0,7536.
